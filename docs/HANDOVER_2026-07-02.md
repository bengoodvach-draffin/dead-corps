### 1.1 Feral pursuit-claim leak (A1) — highest priority
- **Bug:** `zombie.gd` `die()` calls `_pounce.abort()` but never `_feral.clear()`, so a feral killed mid-pursuit (routine since gunfire, 3.1) never calls `GameManager.remove_pursuit()`. Its victim stays "pursued" forever → no feral ever peels onto that straggler again (`FeralBrain._best_fresh_human` skips pursued humans) and the hunted ring stays lit. Commit cb19fb7 wired the *pounce*-claim release on death but the *pursuit* claim was missed — confirmed oversight, not a decision.
- **Fix:** in `die()` (zombie.gd:212–225), call `_feral.clear()` alongside `_pounce.abort()`, **before** the corpse-linger `await`. (`clear()` → `_release_pursuit()` → `remove_pursuit`; it is also used by `_set_calm`, so it's safe on any path.)
- **Optional same-ticket tidy:** `_release_pursuit()` (feral_brain.gd:246–248) skips `remove_pursuit` when the target is already freed, leaving stale freed keys in `_pursuit_counts` — harmless but a leak; consider erasing unconditionally with a valid-check inside GameManager.
- **Invariants touched:** released-is-released (untouched — this is the death path); pounce exclusion (untouched).
- **Test:** release 2 ferals at 2 separated humans near a GI; let the GI shoot one feral mid-chase. Before: its target is never peeled onto by the surviving feral and keeps the faint ring. After: the survivor can divert to it; ring clears. Determinism spot-check per implementer guide §4.3 (boot the scenario twice, diff kill/target logs).

### 1.2 Stop-to-fire (A2 — Ben's ruling)
- **Bug:** the dispatcher writes `facing_direction = velocity.normalized()` every frame (human.gd:232–233), wiping `FillBehavior._rotate_toward`'s per-frame progress — a *moving* defender can only complete the rotation gate within ~21° of its travel direction, so a patroller's hot gun never fires off-axis.
- **Ruled fix — stop-to-fire:** while the fill front is in the *reached* state (rotation gate active, `_fill_front.is_reached()`), the human **halts** — patrol movement suspends, velocity zeroes, and the aim rotation exclusively owns `facing_direction`. After the shot lands (front resets), movement/patrol resumes.
- **Scope care:** halt only in the *reached* state, NOT while merely filling (a walking human with a growing front keeps walking); the fear break must still preempt (fear ticks before fill in the dispatcher — keep that ordering); civilians unaffected (no reached state).
- **Suggested shape:** this is the natural moment to restructure `human.gd`'s `_physics_process` into the rule-4 match dispatcher (`_tick_defending/_tick_fleeing/_tick_cowering`) since the halt logic lives exactly there — but that's optional scope; propose either way first.
- **Test:** militia patrolling left-right; zombie approaches from behind. Before: gun hot, no shot while walking. After: militia stops, turns at 360°/s, fires, resumes patrol. Also verify: two zombies at opposed angles still produce the spec's rotation cost between shots; a break mid-rotation still cancels the shot.

### 1.3 Cowering humans still block firing lanes (B3)
- **Bug:** spec §4.1 (and the 3.1-synced spec text) says corpses AND cowerers don't block; `die()` zeroes `collision_layer` (human.gd:458) but `start_cowering()` (human.gd:423–431) doesn't.
- **Fix:** one line in `start_cowering()`, mirroring `die()`.
- **Check while there:** pounce-kill on a cowerer must still work (it does — pounce is claim/range-based, not collision-based) and escape zones must not react (moot — cowerers never move; and zones detect on the same layer, so note the interaction in the commit message).
- **Test:** shooter → cowerer → zombie in a line: shot now passes. Terror kill on the cowerer still pays +1 mult.
