**Date:** 2026-07-02 · **Scope:** all v2 work on `v2-poc` through commit 80a709f, audited against `ARCHITECTURE_GUIDELINES.md`, `V2_IMPLEMENTER_GUIDE.md` §2, and `V2_DIRECTION_SPEC.md` §3–§10.
**Method:** full read of every v2-touched script (~5,000 lines across 32 files) by three parallel audit passes (zombie side, human side, managers/systems), plus mechanical sweeps (RNG, group scans, underscore cross-reads, §9 tunables, `position` vs `global_position`). Static analysis only — no Godot binary or PowerShell in this environment, so the parse gate and MCP boot checks could not run here.

## Verdict

The v2 architecture is real, not cosmetic — the component decomposition, the registry discipline, and the determinism posture all held through five phases of fast building. But three scripts crossed the ~400-line tripwire silently, two design deltas exist only in code comments ("locked" decisions the spec doesn't contain), and each of the three systems the PoC exists to validate (peel-off, the sacred ratio, combo greed) carries exactly one defect that would silently corrupt the validation verdict. All are cheap to fix; none should survive into the Phase 6 playtest.

## A. Confirmed behavior bugs

### A1. Dead feral never releases its pursuit claim — corrupts the peel-off model (HIGH)
`zombie.gd:212–225` — `die()` aborts an active pounce but never calls `_feral.clear()`, so `FeralBrain._release_pursuit()` (feral_brain.gd:246–248) never runs for a feral killed mid-pursuit. GameManager's own doc-comment promises this path (`game_manager.gd:405`: "…or died") — it is not wired.

Since Phase 3.1, gunfire kills ferals mid-chase routinely. Consequences:
- `_pursuit_counts` keeps the entry forever → `is_pursued(human)` stays true → `_best_fresh_human()` (feral_brain.gd:143) skips that human forever. **No feral will ever peel onto a straggler whose only pursuer was shot** — the one-peeler-per-straggler mechanic degrades exactly in the scenario the PoC validates.
- The "hunted" readability ring stays lit on the human permanently.

Fix shape: `die()` calls `_feral.clear()` alongside `_pounce.abort()`. Related minor leak: `_release_pursuit()` skips `remove_pursuit` when the target is already freed (feral_brain.gd:247), leaving stale freed-object keys in `_pursuit_counts` (harmless — pool getters filter through `living_humans()` — but a dictionary leak).

### A2. Facing tug-of-war: a moving armed defender essentially cannot fire off-axis (HIGH)
`human.gd:232–233` sets `facing_direction = velocity.normalized()` every frame; `FillBehavior._rotate_toward` (fill_behavior.gd:183–197) then rotates from that by at most `turn_speed × delta` (≈6°/frame at 60fps). Rotation progress is discarded each frame, so a **patrolling** armed human can only complete the rotation gate for targets within ~(6° + 15° tolerance) of its travel direction — a hot gun that never discharges at a flanking zombie for as long as the human keeps walking. The comment at human.gd:236–237 believes tick ordering fixes this; it only fixes the single-frame overwrite, not the accumulation. Stationary defenders are unaffected. Needs a stop-to-fire rule or a facing-priority flag.

### A3. GameConfig override leak across scenes (latent — bites at level #2)
`level_config.gd` pushes overrides into the `GameConfig` autoload on `_ready()`, but nothing ever resets the autoload to defaults. Play a level **with** a LevelConfig, then load one **without** → the second level runs the first level's tunables. The header comment (level_config.gd:11–12) is only true from a fresh boot. Restart-same-scene is safe. Fine for the single-level PoC; fix before a second level exists.

### A4. Teardown race: spurious "Defeat!" during scene reset (cosmetic)
`game_manager.gd:220–232` — `_on_zombie_removed`'s teardown guard skips only *alive* zombies exiting the tree. A dead-lingering corpse (zombie.gd keeps corpses in-tree ~0.3s) whose `tree_exiting` fires during a reload can run `check_lose_condition` mid-teardown and emit a spurious `game_lost`.

### A5. Lose instant is coupled to render framerate (edge case)
`zombie.gd:223` — corpse linger uses `await get_tree().create_timer(0.3)` (idle-frame SceneTreeTimer), and `get_total_zombie_count()` (game_manager.gd:450–451) counts corpses via `get_all_zombies()` (validity-filtered, not `is_alive`-filtered). The lose verdict therefore lands ~0.3s of *wall/render* time after the last death — the one place render timing touches a sim decision. Would show up in the §10 boot-twice log diff as a mismatched defeat timestamp. Fix shape: filter the lose count by `is_alive`, or move the linger to physics time.

## B. Spec deviations needing a design ruling (propose-first escapes)

### B1. Combo "tiered base" is not in the spec (§6.1)
`combo_system.gd:46–48`: `_pot += kill_base × ceil(chain / combo_tier_size)` — kills 1–5 worth 10, 6–10 worth 20, etc. The file header claims "spec §6.1, V2 tiered base — locked 2026-06-17", but §6.1 says flat "every kill adds kill_base (10) to the pot", and `combo_tier_size` (game_config.gd:88–91) is absent from the §9 table. Either a real decision's spec sync was skipped, or the implementation extended the model and stamped it "locked." Everything else in the combo (burst +1, terror +1 stacking, bank-on-expiry, held-mult-applies-to-whole-pot, score-at-kill-not-rise, finalize-before-end-screen) matches §6.1 exactly. Reconcile before trusting the PoC's "does the combo create greed" read (validation Q4).

### B2. A friendly-screened gun COOLS instead of holding hot (§4.1, stated twice)
`fill_behavior.gd:81–101` — a zombie in awareness range but screened by other humans makes `_nearest_visible_zombie` return null → the front **decays**. The divergence is self-documented ("the gun cools rather than holding") but spec §4.1 is explicit twice: "a zombie in range but with no clear lane keeps the gun hot but produces no shot" / "if none are clear the gun holds hot until a lane opens", and the implementer-guide invariant repeats it. Rear ranks of a defender knot fully cool their guns — clusters are weakened beyond spec intent, which **distorts the Phase 6 sacred-ratio sweep** (validation Q7). Side effect of the same design: civilians inherit human-screened *perception* (a civilian behind other humans won't react to a visible zombie) — the spec's human-blocking rule was about firing, not awareness. Fix shape: split awareness-LOS (buildings only, mask 1) from lane-LOS (buildings + humans, mask 5); hold `_fill` when in-range-but-screened.

### B3. Cowering humans still block firing lanes (§4.1: they don't)
`start_cowering()` (human.gd:423–431) does not zero `collision_layer`, unlike `die()` (human.gd:458) which correctly does. One line.

### B4. `cower_window` = 2.0 vs spec §9 = 1.2s
`game_config.gd:82` and `level_config.gd:56` both say 2.0 (possibly a copy-slip from `failsafe_window`, also 2.0). Directly changes when huddles form. Sync code or spec.

### B5. Flee exits are not "nearest" by default, and three herding knobs are missing from §9
`flee_behavior.gd:71–95` scores exits by `dist × (1 + bias × alignment-with-threat)` with `flee_exit_threat_bias = 1.5` ON by default (game_config.gd:52) — an exit up to 2.5× farther can win, vs §4.3's "paths to the nearest escape zone." Good herding idea, but it's an unspecced mechanic on by default. `flee_repel_radius` / `flee_repel_strength` / `flee_exit_threat_bias` (and `combo_tier_size`) all exist in config but not in the §9 table.

### B6. Smaller spec gaps
- "Armed humans visually face the nearest zombie between shots" (§4.1 last line) — not implemented; a stationary defender mid-fill keeps stale facing, which also changes the rotation-gate cost profile vs spec (spec's defender is pre-aimed).
- `R` = Restart (§5.1 input sheet) — implemented nowhere; only the debug-overlay Reset button exists.
- Failsafe is **bucketed** (checked every `failsafe_window` — feral_brain.gd:235–243) rather than the spec's rolling window "same detector pattern as cowering"; worst-case detection is 2× window (~4s). Behaviorally near-equivalent; document or align.
- Pounce landing is time-based, not arrival-based (pounce_behavior.gd:81–85) — kills a valid target regardless of final distance. Can't diverge at current tunings; becomes "killed from a distance" if flee speed or flight time is retuned. Also: a target escaping mid-flight yields a kill-less full 1.0s recovery — defensible, but nobody proposed it.
- BOID separation still applies during pounce FLIGHT and RECOVERY (zombie.gd:91–92 run before the pounce tick) — "stationary on the corpse" (§3.5.3) is technically soft.

## C. Architecture-guidelines compliance

### Rule 2 — component decomposition: mostly honored; two components never extracted + one named smell is back
- ✅ Zombie side is the model: `Zombie` (225 lines) is a genuinely thin dispatcher; ShambleBehavior / FeralBrain / PounceBehavior own their mechanics exclusively; FeralBrain↔PounceBehavior never touch (the Result-enum report-up pattern is exemplary). `FeralTargeting` as the single owner of path-score means seeding and pursuit literally cannot drift apart.
- ✅ Human side has FillBehavior / FearDetector / FleeBehavior as real components with clean shell mediation (`cancel_fill`, `start_fleeing`, `start_cowering` all route through the shell).
- ❌ **`PatrolBehavior` was never extracted** — patrol lives entirely in the human.gd shell (exports 59–78, `update_patrol` 251–288, waypoint loading 307–318, editor drawing 527–545): ~120 lines, the single largest contributor to the tripwire breach.
- ❌ **`CowerDetector` was never extracted** — the net-displacement detector lives inline in FleeBehavior (flee_behavior.gd:123–132). Ownership is still singular, so not a rule-1 smear, but the guide scoped 3.5 as "a self-contained detector," and the same detector *shape* is duplicated in FeralBrain's failsafe.

The guidelines name this exact smell ("the `self as Zombie` smell from v1 stays dead"). Fix shape: hoist `facing_direction` to Unit (it's generic — Human uses it too) or move alignment into Zombie.

### Rule 3 — size tripwires: crossed silently, three times
- `human.gd` 570 · `game_manager.gd` 473 · `selection_manager.gd` 464. The guideline's words: "crossing one silently is how 2,854 lines happen."
- Mitigating: composition analysis shows this is **not v1-shaped regrowth**. human.gd's overage is patrol (~120) + interim presentation flagged for the 5.1 move (~110) + dead LOS helpers (~35); its *mechanics* content is ~150 lines. - Recommended splits before Phase 7: PatrolBehavior out of Human; hunt pool + violence pipeline (contagion/risers/gunfire entry) out of GameManager; formation planner out of SelectionManager.

### Rule 4 — dispatcher `_physics_process`
- ✅ zombie.gd:85–103 is a textbook thin dispatcher (~19 lines, `match` → `_tick_calm`/`_tick_feral`).
- ❌ human.gd:192–242 (~51 lines) is an early-return ladder, not a match dispatcher, with inlined logic (stale-state self-correction, break-freeze, movement-facing) and the FLEEING/breaking gate written twice (215/224 vs 238). All heavy logic IS delegated — violation of form at modest scale. A `match` with `_tick_defending/_tick_fleeing/_tick_cowering` would fix it and shed the duplicate gate (and is the natural place to fix bug A2).

### Rule 5 — signals up, calls down: CLEAN
Zero cross-script underscore reads anywhere (grep-verified). External interaction is all methods/signals. One exception: `game_manager.gd:311–325` writes `selection_manager.control_groups[n]` directly (test-scenario convenience path) — a cross-owner write that also skips `assign_control_group`'s cleanup.

### Rule 6 — sim independent of presentation: correct direction; sanctioned interim debt is growing
Simulation never reads a renderer. But the hunted/hover rings, fill-line debug draw, class label, and cower/corpse tints all live in the unit scripts (human.gd:484–570, zombie.gd modulate writes), comment-flagged for the 5.1 move to `vision_renderer` (still a stub). Minor: `is_armed()` = `!= CIVILIAN` (a config `armed` flag would be purer); zombie.gd:194–208 hardcodes per-state BOID tuning as branches (not §9 knobs, but a table would age better).

### Rule 8 — registry-only per-frame discovery: honored
Every per-frame neighbour query goes through `gm.neighbours_within()` / pool getters. `get_nodes_in_group` survivors are all sanctioned or near-sanctioned: `_ready` wiring (game_manager.gd:462/468), input handlers (selection_manager.gd:203/223 — event-driven, though registry would be more consistent AND fix the `position` bug), once-per-break escape-zone lookups (human.gd:372, flee_behavior.gd:83 — zones aren't in the registry; no alternative). ## D. Determinism (spec §10) — the strongest area

- **Zero live RNG** anywhere in scripts/ (grep: only historical comments).
- All variation is DetHash (shamble wander/dwell, formation jitter). det_hash.gd is clean — 31-bit masking, decorrelated sub-seeds, honest same-build scoping.
- Registry ordering contract documented at the definition site and honored by every consumer; `pursued_humans()`/`fleeing_humans()` deliberately filter `living_humans()` instead of iterating the dictionary — someone understood §10, not just obeyed it.
- All sorts are total-ordered with unit_uid tiebreaks (feral_brain.gd:212, release_seeder.gd:38–45); strict `<` everywhere means ties go to lowest uid.
- All gameplay timing is accumulated delta on `_physics_process`.
- Exceptions/nuances: (1) the A5 idle-frame corpse timer — the one render-time value feeding a sim decision; (2) `_release` iterates the assignment Dictionary (selection_manager.gd:309) — deterministic via insertion order but against the invariant's letter (iterate the uid-sorted `ferals` array instead); (3) fill rotation-target can swap between near-equidistant zombies frame-to-frame (no hysteresis) — replay-identical, but facing-jitter readability risk; (4) two risers expiring the same frame rise in reverse insertion order (deterministic, just surprising).

## I. What is genuinely strong (why the foundation IS set up for success)

1. **The component architecture is real.** Zombie is a 225-line dispatcher shell; behaviors are true child components that never touch siblings; the Result-enum report-up pattern makes the feral state machine legible at a glance. FeralTargeting and ReleaseSeeder are model one-owner citizens (pure static math, exhaustive deterministic tiebreaks, shell keeps input+ignition only).
2. **Determinism discipline is pervasive and commented at every decision point** — it will survive contributor (and session) turnover.
3. **Spec↔code fidelity on the hardest logic is near-exact:** peel-off freshness (alive ∧ unclaimed ∧ un-pursued ∧ LOS ∧ forward), the hard-skip-on-peel vs finite-penalty-on-retarget asymmetry, cowering local-scan-only, shared-kill instant retarget, kill-at-landing with mid-flight abort, pounce exclusion with self-healing claims, win/lose including both subtle clauses (cowerers block win; risers block lose), combo burst/terror stacking and bank semantics.
4. **The kill/pounce/escape invariants are airtight across files** — `abort()` releases claims with no kill; `_land()` no-kills escaped targets; gunfire kills mark the zombie dead before the contagion query; the escape barrier holds even mid-pounce because flight moves through velocity, not tweens.
5. **Defensive discipline** — `is_instance_valid` throughout, teardown-vs-death disambiguation, idempotent registration, double-connect guards, fear-before-fill tick ordering making the committed-break invariant airtight by construction.
6. **Known divergences are mostly written down** (the fill-cooling reading, the LOS-override bug) — the failure was not flagging them for a propose-first ruling, not hiding them.
